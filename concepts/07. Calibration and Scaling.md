# Model Calibration & Temperature Scaling

> [!NOTE]
> **Reliability Signals vs. Calibration:** 
> Temperature Scaling is a downstream application. When estimating model reliability, it is often necessary to first prove that a robust reliability signal exists before building any dynamic calibration layer on top of it. This document serves as background theory for such downstream applications.

Comprehensive study notes on neural network calibration — why it fails, how to measure it, and how to fix it. All claims cited. Sources expanded beyond the original reference list to include deep mathematical proofs on scoring rules and advanced post-hoc methods.

Model calibration is the degree to which a model's confidence scores reflect its actual accuracy. A well-calibrated model that says "70% confident" is correct 70% of the time across all such predictions. Miscalibration — especially overconfidence — is a safety-critical failure mode in high-stakes applications like mental health classification, medical diagnosis, and autonomous systems [1][2].

## 1. The Calibration Problem

### 1.1 What Calibration Means

Let $`\hat{p}`$ be the maximum softmax probability output by a classifier. **Perfect calibration** means:

```math
P(\hat{Y} = Y \mid \hat{p} = p) = p \quad \forall p \in [0, 1]
```

In words: among all examples where the model outputs confidence $`p`$, exactly fraction $`p`$ are correctly classified.

**Decomposition:** Calibration can be decomposed into:
- **Sharpness:** How peaked the probability distributions are (concentrated vs. diffuse)
- **Refinement:** Whether confidence scores discriminate between correct and incorrect predictions
- **Calibration proper:** Whether confidence levels match empirical accuracy

A model can be sharp (always outputs 0.9+) but miscalibrated (only 70% accurate). Calibration requires not just sharpness but alignment.

### 1.2 The Empirical Finding: Modern Networks Are Overconfident

Guo et al. [1] conducted the seminal empirical study (2017). Key findings:

**Before Guo et al.:** It was assumed that more accurate models would be better calibrated — "if it gets more right, its confidence should be more reliable."

**After Guo et al.:** Modern deep networks are systematically **more overconfident** than their shallower predecessors, despite being more accurate. Specifically:

| Model | Top-1 Accuracy | ECE (before calibration) | ECE (after temp. scaling) |
| :--- | :--- | :--- | :--- |
| LeNet (1998) | 78.2% | 3.4% | — |
| ResNet-110 | 93.6% | **4.8%** | 0.9% |
| ResNet-110 (SD) | 93.0% | **0.7%** | — |
| DenseNet-40 | 93.0% | **1.3%** | — |
| Wide ResNet-28-10 | 95.3% | **3.4%** | 0.8% |

Deeper networks (more layers) are more overconfident. The finding generalised across architecture types and datasets.

**For NLP:** After fine-tuning BERT on classification tasks, ECE can be 5–15%, depending on the domain and the amount of fine-tuning data.

Modern networks suffer from a severe calibration-accuracy paradox: the architectural choices that increase accuracy (depth, width, Batch Normalization) are the exact same choices that destroy calibration.

## 2. Root Causes of Miscalibration

### 2.1 Model Capacity

Larger, deeper models have higher capacity — they can perfectly fit the training data. When training loss is driven to near zero, the logits become very large (model very confident on training data). This magnitude carries over to test time, producing overconfident predictions even when the model is wrong.

### 2.2 Batch Normalisation

Guo et al. [1] found that models **without** Batch Normalisation (e.g., ResNet with Stochastic Depth) are better calibrated. Batch Norm normalises activations during training — but at test time, statistics differ. This creates a training-test mismatch that inflates logit magnitudes at test time.

### 2.3 Weight Decay (L2 Regularisation)

Counterintuitively, **too little** weight decay → overconfidence (large logit magnitudes). **Appropriate** weight decay penalises large weights, keeping logit magnitudes smaller and distribution softer. But modern training recipes often use very small weight decay for large pre-trained models, contributing to overconfidence.

### 2.4 Training Duration

Training for too many epochs drives the model toward very confident training predictions. **Early stopping** or **regularisation** helps calibration at the cost of some accuracy. The accuracy-calibration trade-off is real.

### 2.5 Domain Shift

Even a well-calibrated in-domain model becomes overconfident on OOD inputs. The model's internal representations map OOD inputs to familiar in-distribution representations — but the decision boundaries were learned on in-distribution data. The model confidently predicts an incorrect class.

## 3. Measuring Calibration

### 3.1 Expected Calibration Error (ECE)

The standard metric [2]. Sort $`n`$ test predictions by confidence, bin them into $`M`$ equal-width bins $`B_1, \ldots, B_M`$ (typically $`M = 15`$):

```math
\text{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|
```

where:
- $`\text{acc}(B_m) = \frac{1}{|B_m|} \sum_{i \in B_m} \mathbb{1}[\hat{y}_i = y_i]`$  (fraction correct in bin)
- $`\text{conf}(B_m) = \frac{1}{|B_m|} \sum_{i \in B_m} \hat{p}_i`$   (mean confidence in bin)

**Limitation:** ECE is sensitive to binning scheme — equal-width bins may leave some bins empty if the model is extreme (all predictions near 0 or 1). **Adaptive binning** (equal-count bins) is more robust.

### 3.2 Maximum Calibration Error (MCE)

```math
\text{MCE} = \max_{m \in \{1,\ldots,M\}} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|
```

The worst-case bin calibration error — important for safety-critical applications where individual high-confidence predictions matter.

### 3.3 Negative Log-Likelihood (NLL)

```math
\text{NLL} = -\frac{1}{n} \sum_{i=1}^{n} \log \hat{p}_{y_i}
```

A proper scoring rule that penalises both poor discrimination and poor calibration. A calibrated model minimises NLL exactly. The advantage: NLL doesn't require binning, avoiding binning artefacts.

### 3.4 Brier Score and its Decomposition

The Brier Score [7] is defined as the mean squared error of the probability forecasts:

```math
\text{Brier} = \frac{1}{n} \sum_{i=1}^{n} \|\hat{\mathbf{p}}_i - \mathbf{y}_i\|^2
```

where $`\hat{\mathbf{p}}_i`$ is the full probability vector and $`\mathbf{y}_i`$ is the one-hot true label. The Brier score famously decomposes into three components:

```math
\text{Brier} = \text{Reliability} - \text{Resolution} + \text{Uncertainty}
```

1. **Reliability (Calibration):** Measures how close the forecast probabilities are to the true frequencies (lower is better).
2. **Resolution:** Measures how much the conditional probabilities differ from the climatic average (higher is better).
3. **Uncertainty:** The variance of the observations, independent of the model.

This decomposition enables strict mathematical attribution of miscalibration to specific factors.

## 4. Post-Hoc Calibration Methods

These methods do not retrain the model — they add a transformation $`f`$ after the model's logits:

```math
\hat{\mathbf{p}}_{calibrated} = \text{softmax}(f(z))
```

A small **held-out calibration set** (typically 10–15% of the data, **separate from** the test set) is used to fit $`f`$.

### 4.1 Temperature Scaling

The simplest and most empirically effective method [1]:

```math
f(z) = z / T, \quad T \in \mathbb{R}^+
```

A single scalar $`T`$ is optimised to minimise NLL on the calibration set:

```math
T^* = \arg\min_{T} \text{NLL}_{cal}(T) = \arg\min_{T} -\sum_{i} \log \hat{p}_{y_i}(T)
```

This is a 1D convex optimisation — can be solved with LBFGS in seconds.

**Why $`T > 1`$ usually?** Because modern networks are overconfident, we need to increase $`T`$ to soften the distribution. $`T > 1`$ reduces logit magnitude, pushes probabilities toward $`1/C`$, and reduces ECE.

**Key property:** Temperature scaling does not change the predicted class (argmax is invariant to scaling), only the confidence level. It also preserves the ranking of class probabilities.

**Limitation of standard Temperature Scaling:** A single global $`T`$ assumes all inputs are miscalibrated to the same degree. In practice, different inputs (in-domain vs. OOD, common vocabulary vs. clinical terminology) may require different temperatures — motivating **input-dependent (adaptive) temperature scaling** methods.

### 4.2 Platt Scaling

Originally developed for SVMs, extended to neural networks [1]. Fits a logistic regression on top of the model's logit vector:

```math
f(z) = az + b, \quad a, b \in \mathbb{R}
```

For multi-class: generalises to a linear layer $`f(z) = Az + b`$ where $`A \in \mathbb{R}^{C \times C}`$. More flexible than temperature scaling but requires estimating $`C^2 + C`$ parameters — can overfit on small calibration sets.

**Relationship to temperature scaling:** Temperature scaling is Platt scaling with the constraint $`A = (1/T)I`$ (isotropic scaling) and $`b = 0`$.

### 4.3 Vector Scaling

A compromise between temperature scaling and full Platt scaling [1]:

```math
f(z) = z \odot w + b, \quad w, b \in \mathbb{R}^C
```

Separate scale and bias per class. Allows the model to recalibrate classes with different base rates without the full $`C^2`$ parameters of Platt scaling.

### 4.4 Isotonic Regression

A non-parametric calibration method [1][3]:

Given predictions sorted by confidence, fit a non-decreasing step function $`g: [0,1] \to [0,1]`$ such that $`g(\hat{p}) \approx \text{empirical accuracy at confidence } \hat{p}`$.

- **Advantage:** No parametric assumption — can fit any calibration curve
- **Disadvantage:** Requires more data; prone to overfitting on small calibration sets

### 4.5 Histogram Binning

Assign a constant calibrated probability to each bin: all predictions in bin $`m`$ receive confidence $`\text{acc}(B_m)`$.

- Extremely simple, zero parameters
- Non-smooth: abrupt changes at bin boundaries
- Performance degrades for rare confidence levels

### 4.6 Dirichlet Calibration

For multi-class settings, fit a Dirichlet distribution over the softmax simplex [4]:

```math
g(\hat{p}) = \text{softmax}(A \log \hat{p} + b)
```

This is equivalent to applying a linear transformation in log-probability space. It captures class-to-class interactions that vector scaling misses — important when classes have correlated miscalibration patterns (e.g., depression and anxiety are often confused).

## 5. Comparison of Calibration Methods

| Method | Parameters | Flexibility | Calibration set size needed | Accuracy impact |
| :--- | :--- | :--- | :--- | :--- |
| Temperature Scaling | 1 | Low | ~500 examples | None (ranking preserved) |
| Vector Scaling | $`2C`$ | Medium | ~2,000 examples | None |
| Platt Scaling | $`C^2 + C`$ | High | ~5,000+ examples | None |
| Isotonic Regression | Non-param | Very High | ~5,000+ examples | None |
| Dirichlet Calibration | $`C^2 + C`$ | High | ~5,000+ examples | None |
| Label Smoothing | N/A (training) | N/A | Full training set | Slight drop possible |

## 6. Training-Time Calibration Methods

Unlike post-hoc methods, these affect the model during training.

### 6.1 Label Smoothing

Replace one-hot targets with **soft targets**:

```math
\tilde{y}_j = \begin{cases} 1 - \epsilon + \epsilon/C & \text{if } j = y \\ \epsilon/C & \text{if } j \neq y \end{cases}
```

With $`\epsilon = 0.1`$: the true class target is 0.9 instead of 1.0, and all other classes get 0.011 instead of 0.

**Effect:** Prevents the model from driving logits to extreme values (since the target is never exactly 1). This directly regularises logit magnitudes, improving calibration.

**Caveat [2]:** Label smoothing improves calibration but makes the model's probability outputs less interpretable as likelihoods — they become "smoothed" probabilities rather than class probabilities.

### 6.2 Mixup Training

Interpolate between training examples linearly:

```math
\tilde{x} = \lambda x_i + (1-\lambda) x_j, \quad \tilde{y} = \lambda y_i + (1-\lambda) y_j, \quad \lambda \sim \text{Beta}(\alpha, \alpha)
```

Trains the model to output mixtures of probabilities for interpolated inputs, creating a smoother decision boundary. Empirically improves calibration [2].

### 6.3 Focal Loss

Originally for object detection, increasingly used for calibration:

```math
\mathcal{L}_{focal} = -(1 - \hat{p}_y)^\gamma \log \hat{p}_y
```

When the model is very confident ($`\hat{p}_y \to 1`$), the factor $`(1-\hat{p}_y)^\gamma \to 0`$ reduces the loss — less encouragement to be even more confident. When the model is uncertain ($`\hat{p}_y \to 0`$), the factor is near 1 — full loss signal to improve.

**Effect:** Focal loss naturally prevents overconfidence by not rewarding already-confident predictions.

## 7. Calibration for NLP: Special Considerations

### 7.1 Pre-training + Fine-tuning Calibration Shift

BERT-style models undergo two phases of training:
1. **Pre-training:** Masked LM on large corpus — representations are not calibrated for downstream classification
2. **Fine-tuning:** Classification objective — model rapidly converges, driving logits large and miscalibrating

This two-phase process creates a characteristic miscalibration pattern: the model is very confident very quickly after fine-tuning, even before it has enough examples to justify that confidence.

**Observation:** With fewer fine-tuning examples, ECE tends to be higher — the model overfits the training set distribution in terms of confidence [2].

### 7.2 Class Imbalance and Calibration

Mental health datasets are inherently imbalanced — "normal" posts far outnumber crisis posts. Imbalanced training:
- Drives the model to assign low probability to rare classes
- ECE on rare classes is often much higher than overall ECE
- Temperature scaling with a single $`T`$ cannot correct per-class miscalibration

**Solutions:**
- Class-weighted loss during fine-tuning
- Per-class temperature scaling (vector scaling)

### 7.3 In-Distribution vs. OOD Calibration

A model can be well-calibrated on in-distribution test examples but severely miscalibrated on OOD inputs. Selective calibration — using temperature scaling only for inputs predicted to be in-distribution — is an active research direction.

## 8. Official Temperature Scaling Implementation

The reference implementation [5] by Guo et al.:

```python
class TemperatureScaling(nn.Module):
    def __init__(self):
        super().__init__()
        self.temperature = nn.Parameter(torch.ones(1) * 1.5)

    def forward(self, logits):
        return self.temperature_scale(logits)

    def temperature_scale(self, logits):
        temperature = self.temperature.unsqueeze(1).expand(
            logits.size(0), logits.size(1)
        )
        return logits / temperature

    def calibrate(self, logits_val, labels_val):
        optimizer = optim.LBFGS([self.temperature], lr=0.01, max_iter=50)
        nll_criterion = nn.CrossEntropyLoss()

        def eval():
            optimizer.zero_grad()
            loss = nll_criterion(self.temperature_scale(logits_val), labels_val)
            loss.backward()
            return loss

        optimizer.step(eval)
        return self
```
