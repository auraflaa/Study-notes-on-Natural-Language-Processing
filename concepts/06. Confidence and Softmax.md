# Confidence Scores & Softmax

Comprehensive study notes on the softmax function, its mathematical foundations, information-theoretic properties, gradient dynamics, failure modes, and alternatives. All claims cited. Sources cover Goodfellow et al., Jurafsky & Martin, and key calibration literature.

Confidence scores derived from the softmax function are the primary interface through which a neural classifier communicates its uncertainty. Every downstream decision — whether to trust a prediction, trigger escalation, or apply calibration — depends on the quality of these scores. Understanding softmax at depth — its geometry, its gradient behaviour, its pathologies, and its alternatives — is a prerequisite for meaningful work on calibration and reliability estimation [1][2][3].

---

## 1. The Classification Problem: From Features to Probabilities

### 1.1 The Architecture Chain

A neural classifier for mental health text operates as a composed function:

```
Raw text x
    │
    ▼
Tokeniser → [CLS, token₁, ..., tokenₙ, SEP]
    │
    ▼
BERT/MentalBERT encoder (12 layers, 768 dims)
    │
    ▼
h = h_{[CLS]} ∈ ℝ^768    ← penultimate representation
    │
    ▼
z = Wh + b,  W ∈ ℝ^{C×768},  b ∈ ℝ^C   ← logits
    │
    ▼
p̂ = softmax(z)   ∈ Δ^{C-1}   ← confidence scores
    │
    ▼
ŷ = argmax p̂   ← predicted class
```

Each stage is deterministic and differentiable. The entire chain is trained end-to-end. The **logit vector** $`z`$ is the raw model output before normalisation. The **confidence score vector** $`\hat{p}`$ is the softmax-normalised version.

### 1.2 What "Confidence" Should Mean

A confidence score $`\hat{p}_j`$ for class $`j`$ should represent: *"given this input, what fraction of the time would the true label be class $`j`$?"*

This is a **frequentist** interpretation of probability. For it to be meaningful, the model must be **calibrated**: $`\hat{p}_j = P(Y = j \mid X = x, \hat{p}_j = p)`$.

In practice, modern neural networks are systematically miscalibrated — the number they output as "confidence" does not match the empirical accuracy at that confidence level [4]. This is the core problem that calibration research addresses.

## 2. The Softmax Function: Complete Mathematical Analysis

### 2.1 Definition

```math
\hat{p}_j = \text{softmax}(z)_j = \frac{e^{z_j}}{\sum_{k=1}^{C} e^{z_k}}, \quad j = 1, \ldots, C
```

**Fundamental properties:**
- **Range:** $`\hat{p}_j \in (0, 1)`$ for all $`j`$ — strictly positive, never exactly 0 or 1 regardless of logit values (the exponential function is always strictly positive)
- **Normalisation:** $`\sum_{j=1}^{C} \hat{p}_j = 1`$ exactly — the output lies on the probability simplex $`\Delta^{C-1}`$
- **Monotonicity:** Higher $`z_j`$ → higher $`\hat{p}_j`$; the function preserves the logit ranking
- **Translation invariance:** $`\text{softmax}(z) = \text{softmax}(z + c\mathbf{1})`$ for any constant $`c`$ (adding a constant to all logits doesn't change the output). This is why temperature scaling works identically whether applied to raw or shifted logits.
- **Scale sensitivity:** $`\text{softmax}(\lambda z) \neq \lambda \cdot \text{softmax}(z)`$ — scaling by a constant dramatically changes the distribution (this is temperature scaling)

**Relationship to argmax:**
```math
\lim_{\lambda \to \infty} \text{softmax}(\lambda z)_j = \begin{cases} 1 & \text{if } j = \arg\max_k z_k \\ 0 & \text{otherwise} \end{cases}
```

```math
\text{softmax}(0 \cdot z)_j = \frac{1}{C} \quad \forall j
```

Softmax interpolates continuously between uniform distribution (all logits zero) and one-hot argmax (logits scaled to infinity). This is the precise sense in which it is a "soft" maximum [1].

### 2.2 Worked Example: 4-Class Mental Health Classification

Model outputs logits from the linear projection layer:

```
Depression: z₁ = 2.1
Anxiety:    z₂ = 0.8
PTSD:       z₃ = -0.3
Normal:     z₄ = 1.5
```

**Step 1:** Compute exponentials

| Class | $`z_j`$ | $`e^{z_j}`$ |
| :--- | :--- | :--- |
| Depression | 2.1 | 8.166 |
| Anxiety | 0.8 | 2.226 |
| PTSD | −0.3 | 0.741 |
| Normal | 1.5 | 4.482 |
| **Sum** | — | **15.615** |

**Step 2:** Normalise
```math
\hat{p} = (8.166/15.615, \; 2.226/15.615, \; 0.741/15.615, \; 4.482/15.615) = (0.523, \; 0.143, \; 0.047, \; 0.287)
```

**Observations:**
- The gap between $`z_1 = 2.1`$ and $`z_2 = 0.8`$ is 1.3 logit units, but in probability space the gap is $`0.523 - 0.143 = 0.380`$
- Even the lowest-logit class (PTSD, $`z_3 = -0.3`$) receives 4.7% probability — softmax cannot output zero
- The entropy of this distribution: $`H(\hat{p}) = -(0.523\log_2 0.523 + \ldots) = 1.67`$ bits (out of maximum $`\log_2 4 = 2`$ bits)

### 2.3 The Logit Geometry: What the Numbers Actually Mean

The logit $`z_j = W_j h + b_j`$ is a **linear function** of the penultimate representation $`h \in \mathbb{R}^d`$. It measures the **inner product** of the weight vector $`W_j`$ (the "template" for class $`j`$) with $`h`$ (the feature vector of the input).

**Decision boundary:** The boundary between class $`i`$ and class $`j`$ is the set of $`h`$ where $`z_i = z_j`$:

```math
(W_i - W_j)h + (b_i - b_j) = 0
```

This is a hyperplane in $`\mathbb{R}^d`$. The signed distance from $`h`$ to this hyperplane is:

```math
\frac{(W_i - W_j)h + (b_i - b_j)}{\|W_i - W_j\|_2}
```

The logit difference $`z_i - z_j`$ is proportional to this distance. When $`z_i - z_j`$ is large and positive, input $`h`$ is far from the decision boundary on the side of class $`i`$ — and softmax assigns high probability to class $`i`$.

**Crucial implication:** Softmax confidence reflects distance from decision boundaries in the learned feature space. It does NOT inherently reflect proximity to training data. An OOD input can be far from any training example yet still be far from all decision boundaries (and thus appear confident) if its features happen to strongly activate one class weight vector.

## 3. Numerical Implementation

### 3.1 The Overflow Problem in Float32

IEEE 754 float32 can represent values up to approximately $`3.4 \times 10^{38}`$. The function $`e^x`$ exceeds this at $`x \approx 88.7`$. For typical fine-tuned BERT logits which can be in the range $`[-20, 20]`$, this is safe — but adversarial inputs or early training instability can produce extreme logits.

### 3.2 The Numerically Stable Implementation

**Mathematical equivalence:** Adding a constant $`c`$ to all logits before exponentiation cancels exactly:

```math
\frac{e^{z_j - c}}{\sum_k e^{z_k - c}} = \frac{e^{z_j} \cdot e^{-c}}{\sum_k e^{z_k} \cdot e^{-c}} = \frac{e^{z_j}}{\sum_k e^{z_k}}
```

**Standard choice:** $`c = \max_k z_k`$. This ensures all exponents are $`\leq 0`$, so all values are in $`(0, 1]`$.

```python
import torch
import torch.nn.functional as F

def stable_softmax(logits: torch.Tensor, dim: int = -1) -> torch.Tensor:
    """
    Numerically stable softmax via max subtraction.
    logits: arbitrary shape, softmax applied along `dim`
    """
    # Subtract max for numerical stability
    z = logits - logits.max(dim=dim, keepdim=True).values
    exp_z = torch.exp(z)
    return exp_z / exp_z.sum(dim=dim, keepdim=True)

# PyTorch's built-in is equivalent and uses optimised CUDA kernels:
p = F.softmax(logits, dim=-1)
```

### 3.3 Log-Softmax: The Preferred Numerically Stable Form

For loss computation, it is more numerically stable to compute log-softmax directly:

```math
\log \hat{p}_j = z_j - \log \sum_k e^{z_k} = z_j - \underbrace{(z_{max} + \log \sum_k e^{z_k - z_{max}})}_{\text{log-sum-exp}}
```

```python
# Direct: most numerically stable, single CUDA kernel
log_p = F.log_softmax(logits, dim=-1)   # (batch, C)

# Cross-entropy loss — never do softmax then log separately
loss = F.cross_entropy(logits, targets)  # Internally: -log_softmax + NLL
# Equivalent to:
loss = F.nll_loss(F.log_softmax(logits, dim=-1), targets)
```

**Why `F.cross_entropy` over `softmax` → `log` → `nll_loss`?** The separate chain computes softmax (exponentiation), then takes log (undoing the exponentiation) — numerically redundant and prone to catastrophic cancellation. The fused `cross_entropy` applies the log-sum-exp trick directly.

## 4. Cross-Entropy Loss: The Mathematical Connection

### 4.1 Information-Theoretic Foundation

Cross-entropy between the true distribution $`p(y)`$ (one-hot for class $`y`$) and predicted distribution $`\hat{p}`$ is:

```math
H(p, \hat{p}) = -\sum_{j=1}^C p(y = j) \log \hat{p}_j = -\log \hat{p}_y
```

This equals the **negative log-likelihood** of the true class under the model. Minimising cross-entropy is equivalent to **maximum likelihood estimation** — finding the parameters that make the observed labels most probable under the model.

**Connection to KL divergence:**
```math
\text{KL}(p \| \hat{p}) = H(p, \hat{p}) - H(p)
```

Since $`H(p) = 0`$ for deterministic one-hot labels, minimising cross-entropy is identical to minimising KL divergence from the label distribution to the model's distribution.

### 4.2 The Gradient: An Elegant Formula

**Loss as a function of logits (not probabilities):**

```math
\mathcal{L}(z) = -z_y + \log \sum_{k} e^{z_k}
```

**Gradient with respect to logit $`z_j`$:**

For $`j \neq y`$:
```math
\frac{\partial \mathcal{L}}{\partial z_j} = \frac{e^{z_j}}{\sum_k e^{z_k}} = \hat{p}_j
```

For $`j = y`$:
```math
\frac{\partial \mathcal{L}}{\partial z_y} = -1 + \hat{p}_y = \hat{p}_y - 1
```

Combined:
```math
\boxed{\frac{\partial \mathcal{L}}{\partial z_j} = \hat{p}_j - \mathbb{1}[j = y]}
```

**This formula has profound implications:**
- The gradient is the vector difference between the predicted distribution $`\hat{p}`$ and the one-hot true label $`\mathbf{e}_y`$
- When $`\hat{p}_y \to 1`$ (very confident, correct): gradient $`\to 0`$ — no more update needed
- When $`\hat{p}_y \to 0`$ (very uncertain or wrong): gradient approaches maximum magnitude ($`-1`$ for correct class, $`\hat{p}_j`$ for wrong classes)
- The model naturally provides large correction signals when it is wrong and small signals when it is right

### 4.3 Gradient Saturation and Training Dynamics

**Key problem:** When $`\hat{p}_y \to 1`$ (even if the model is correct by chance on training data), the gradient saturates to zero — learning stops. This is the "confident wrong answer" failure mode:

1. Model accidentally achieves $`\hat{p}_y = 0.99`$ on a training example (possibly by memorising)
2. Gradient for this example: $`\partial \mathcal{L}/\partial z_y = 0.99 - 1 = -0.01`$ (tiny)
3. Model receives almost no correction signal
4. The learned representation $`h`$ for similar inputs remains poorly calibrated

**Solution:** Label smoothing prevents $`\hat{p}_y = 1`$ from being the target, maintaining non-zero gradients throughout training.

### 4.4 The Jacobian of Softmax

The full Jacobian of softmax (how output changes with input) is:

```math
\frac{\partial \hat{p}_j}{\partial z_k} = \begin{cases} \hat{p}_j(1 - \hat{p}_j) & \text{if } j = k \\ -\hat{p}_j \hat{p}_k & \text{if } j \neq k \end{cases}
```

In matrix form: $`J = \text{diag}(\hat{p}) - \hat{p}\hat{p}^T`$

**Key observations:**
- The Jacobian has rank $`C - 1`$ — softmax maps $`\mathbb{R}^C`$ into the $`C-1`$ dimensional simplex, losing one degree of freedom
- The vector $`\mathbf{1}`$ is in the null space: $`J\mathbf{1} = 0`$ — uniform shifts of logits produce zero gradient (translation invariance)
- When one class dominates ($`\hat{p}_j \to 1`$): the diagonal entry $`\hat{p}_j(1-\hat{p}_j) \to 0`$ and all off-diagonal entries involving class $`j`$ also $`\to 0`$ — the Jacobian vanishes, causing gradient saturation

## 5. Temperature Scaling: Full Analysis

### 5.1 Definition and Effect

Temperature scaling modifies softmax by dividing all logits by a scalar $`T > 0`$:

```math
\hat{p}_j(T) = \frac{e^{z_j/T}}{\sum_k e^{z_k/T}}
```

**Equivalence to logit scaling:** Temperature $`T`$ is equivalent to multiplying all logit differences by $`1/T`$. The decision boundary (where $`z_i = z_j`$) is unchanged, but the **rate at which probability accumulates away from the boundary** changes.

### 5.2 Continuous Temperature Behaviour

**Worked example** (mental health 4-class, same logits $`z = [2.1, 0.8, -0.3, 1.5]`$):

| $`T`$ | P(Dep) | P(Anx) | P(PTSD) | P(Norm) | $`H`$ (bits) | $`\max \hat{p}`$ |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 0.25 | 0.982 | 0.003 | 0.000 | 0.015 | 0.16 | 0.982 |
| 0.5 | 0.773 | 0.091 | 0.007 | 0.129 | 0.71 | 0.773 |
| 1.0 | 0.523 | 0.143 | 0.047 | 0.287 | 1.67 | 0.523 |
| 2.0 | 0.360 | 0.193 | 0.119 | 0.328 | 1.93 | 0.360 |
| 5.0 | 0.280 | 0.226 | 0.187 | 0.307 | 1.99 | 0.280 |
| 10.0 | 0.264 | 0.243 | 0.234 | 0.259 | 2.00 | 0.264 |
| ∞ | 0.250 | 0.250 | 0.250 | 0.250 | 2.00 | 0.250 |

**Entropy increases monotonically** with $`T`$. At $`T=0.25`$: the distribution is nearly argmax (98.2% on Depression). At $`T=10`$: nearly uniform. The entropy $`H(\hat{p}(T))`$ provides a complete characterisation of distribution sharpness.

### 5.3 Temperature and the Information-Theoretic View

The entropy of the softmax distribution as a function of $`T`$ follows a smooth sigmoid-like curve from 0 (at $`T \to 0`$) to $`\log_2 C`$ (at $`T \to \infty`$). The rate of increase depends on the logit spread $`\max_j z_j - \min_j z_j`$.

For **well-separated logits** (large spread): entropy increases slowly from $`T=1`$, meaning the distribution remains sharp even at moderate temperatures. These are cases where the model is genuinely confident.

For **compressed logits** (small spread): entropy is already high at $`T=1`$, meaning the model is already uncertain. These may not need large temperature increases.

**Practical implication:** The optimal temperature is not just a function of how much to soften the distribution, but of how sharp the distribution already is — which depends on both the logit spread and the linguistic difficulty of the input.

### 5.4 The Softmax Temperature as an Energy Concept

In statistical physics, the Boltzmann distribution over states with energies $`E_j`$ at temperature $`T`$ is:

```math
p_j \propto e^{-E_j/T}
```

The softmax with temperature is identical in form, interpreting **negative logits as energies**: $`E_j = -z_j`$. High temperature = more thermal noise = more uniform distribution. Low temperature = system settles into lowest-energy state. This physical analogy is not a coincidence — energy-based models (see OOD notes) formalise this connection.

## 6. The Overconfidence Problem: Mechanisms and Evidence

### 6.1 Empirical Evidence

Guo et al. [4] conducted the seminal study on neural network miscalibration. They trained modern architectures (ResNet, DenseNet, Wide ResNet) on CIFAR-100 and found:

- **ResNet-110 ECE before calibration: 4.8%** — on average, the model's confidence is 4.8 percentage points higher than its actual accuracy
- **After temperature scaling: ECE = 0.9%** — one scalar parameter fixes most of the problem
- **Key finding:** More accurate models (deeper, wider) tend to be MORE miscalibrated, not less

**The accuracy-calibration inversion:** The correlation between top-1 accuracy and ECE is **positive** for modern architectures — higher accuracy comes with more overconfidence.

Deeper models develop larger logit magnitudes. The final linear layer's weight vectors $`W_j`$ grow during training as the model drives cross-entropy loss to zero. Large $`\|W_j\|`$ → large logits → overconfident softmax.

### 6.2 Mechanistic Analysis: Why Large Logits Develop

Consider a binary classification with logits $`z_1, z_2`$. The softmax output is:

```math
\hat{p}_1 = \sigma(z_1 - z_2) = \frac{1}{1 + e^{-(z_1 - z_2)}}
```

For perfect cross-entropy minimisation on a training set with deterministic labels, the optimal solution is $`z_1 - z_2 \to +\infty`$ (or $`\to -\infty`$) for every training example. The gradient descent trajectory moves the logit difference toward infinity — there is no finite optimum.

Regularisation (weight decay) provides a counterforce, but modern training recipes use very small weight decay for large pre-trained models. The result: logits grow substantially during fine-tuning, producing systematic overconfidence.

### 6.3 The OOD Confidence Failure

Nguyen et al. [5] showed that neural networks can produce near-unity softmax confidence on inputs that are completely unrecognisable to humans — e.g., random pixel noise or adversarial patterns. The mechanism:

```
Random noise input x_noise
    │
    ▼
Feature extractor h(x_noise) — some arbitrary vector in ℝ^768
    │
    ▼
Linear projection z = Wh — may happen to strongly activate z_k for some k
    │
    ▼
softmax(z) — e^{z_k} ≫ others → p̂_k ≈ 1
```

The softmax has no mechanism to say "this input doesn't look like any training example" — it always normalises to a valid probability distribution. The result is a confident wrong prediction.

**Quantitative example:** On a 10-class classifier, a random noise input should receive approximately uniform probability (10% per class). Instead, studies show random noise inputs can receive 90%+ confidence on a single class [5].

### 6.4 Domain Shift and BERT Fine-Tuning

For BERT-based mental health classifiers, the overconfidence problem is exacerbated by the fine-tuning procedure. Pre-trained BERT has broad, well-distributed representations. After fine-tuning on a small mental health dataset:

1. The classification head $`W`$ adapts rapidly (few epochs, small LR)
2. BERT's representations partially shift toward the fine-tuning domain
3. Logit magnitudes increase significantly
4. ECE grows to 8–15% on in-domain test data

On OOD inputs (clinical jargon, different registers):
- The representation $`h`$ is unusual — but the linear layer still projects it onto familiar-seeming class directions
- Softmax produces confident predictions that are wrong

This is the core failure mode that post-hoc calibration attempts to address.

## 7. Information-Theoretic Properties of Softmax Output

### 7.1 Entropy as Uncertainty

Shannon entropy of the softmax distribution:

```math
H(\hat{p}) = -\sum_{j=1}^{C} \hat{p}_j \log_2 \hat{p}_j \quad \text{(bits)}
```

**Bounds:**
- $`H_{\min} = 0`$: one class has probability 1 (argmax)
- $`H_{\max} = \log_2 C`$: uniform distribution (maximum uncertainty)

For 4-class mental health ($`C = 4`$): $`H_{\max} = 2`$ bits.

**Entropy as a calibration signal:**
- High entropy ($`H \approx H_{\max}`$): model is already uncertain — any further temperature increase has diminishing returns
- Low entropy ($`H \approx 0`$): model is very confident — may or may not be justified. Calibration analysis needed.
- The relationship between entropy and actual accuracy is the reliability diagram.

### 7.2 Mutual Information Decomposition

For an ensemble of models or multiple softmax draws, total uncertainty decomposes as:

```math
\underbrace{H(\mathbb{E}_\theta[\hat{p}_\theta])}_{\text{total uncertainty}} = \underbrace{\mathbb{E}_\theta[H(\hat{p}_\theta)]}_{\text{aleatoric}} + \underbrace{H(\mathbb{E}_\theta[\hat{p}_\theta]) - \mathbb{E}_\theta[H(\hat{p}_\theta)]}_{\text{epistemic (mutual information)}}
```

- **Aleatoric uncertainty:** Average entropy of individual model predictions — inherent data ambiguity
- **Epistemic uncertainty:** Mutual information between model parameters and predictions — reduces with more data

For a single deterministic model ($`\hat{p}_\theta`$ is fixed for given $`x`$), this decomposition requires multiple models (ensemble) or multiple samples (MC Dropout).

### 7.3 Predictive Confidence and the Proper Scoring Rule

A **proper scoring rule** is a loss function $`S(\hat{p}, y)`$ such that the expected score is minimised when $`\hat{p} = P(Y \mid X)`$ — the true conditional distribution. This ensures that the optimal strategy for the model is to output true probabilities.

**Cross-entropy is a proper scoring rule.** Training with cross-entropy incentivises the model to output true probabilities — in theory. In practice, finite data, model misspecification, and optimisation dynamics prevent perfect calibration.

**The Brier score** $`\|\hat{p} - \mathbf{e}_y\|^2`$ is also proper and gives less weight to catastrophic failures (heavily wrong predictions). The choice of proper scoring rule affects which regions of miscalibration the training process prioritises correcting.

## 8. Softmax Alternatives: Trade-offs and Applications

### 8.1 Sigmoid for Multi-Label Classification

When classes are not mutually exclusive, replace the shared normalisation with independent binary outputs:

```math
\hat{p}_j = \sigma(z_j) = \frac{1}{1 + e^{-z_j}}, \quad \text{independently for each } j
```

**Gradient:** $`\partial \mathcal{L}_{BCE}/\partial z_j = \hat{p}_j - y_j`$ — same elegant form as softmax cross-entropy, but per-class independently.

**Trade-offs vs. softmax:**

| | Softmax | Sigmoid (multi-label) |
| :--- | :--- | :--- |
| Class relationship | Mutually exclusive (competitive normalisation) | Independent (no competition) |
| Probabilities sum to | Exactly 1 | Anywhere in $`[0, C]`$ |
| OOD behaviour | Forced to pick a class | Can assign low probability to all classes |
| Mental health use | Single-diagnosis classification | Comorbidity (depression AND anxiety) |
| Calibration | Hard (single T governs all classes) | Harder (each class needs independent calibration) |

**The OOD advantage of sigmoid:** Since sigmoid outputs don't sum to 1, a model can output low probability for ALL classes simultaneously — naturally expressing "this input doesn't look like any known condition." Softmax cannot do this — it always redistributes probability to at least one class.

### 8.2 Sparsemax: Exact Zero Probabilities

Sparsemax [6] (Martins & Astudillo, 2016) replaces the softmax normalisation with a Euclidean projection onto the simplex:

```math
\text{sparsemax}(z) = \arg\min_{p \in \Delta^{C-1}} \|p - z\|^2_2
```

The closed-form solution: sort logits $`z_{[1]} \geq z_{[2]} \geq \ldots \geq z_{[C]}`$, find $`k = \max\{j : 1 + jz_{[j]} > \sum_{i \leq j} z_{[i]}\}`$, then:

```math
\hat{p}_j = \max(z_j - \tau, 0), \quad \tau = \frac{\sum_{i \leq k} z_{[i]} - 1}{k}
```

**Key property:** Sparsemax can assign exactly 0 to classes with low logits — producing a genuinely sparse distribution. This is interpretable: "I am certain this is NOT PTSD."

**Gradient:** Sparse — only non-zero classes contribute to the gradient. This can make training more efficient but less smooth.

**Sparsemax vs. Softmax:**

| Property | Softmax | Sparsemax |
| :--- | :--- | :--- |
| Support | Always all $`C`$ classes | Subset of classes (sparse) |
| Differentiability | Smooth everywhere | Non-smooth at sparsity boundaries |
| Interpretability | Probability smoothly distributed | Explicit "this is impossible" (zero) |
| OOD behaviour | Spreads probability across classes | Can assign zero to all except one |
| Training stability | Very stable | Can oscillate near sparsity boundaries |

### 8.3 Entmax: Generalising the Family

$`\alpha`$-entmax [7] (Peters et al., 2019) generalises both softmax ($`\alpha = 1`$) and sparsemax ($`\alpha = 2`$):

```math
\text{entmax}_\alpha(z) = \arg\max_{p \in \Delta^{C-1}} \left[ p \cdot z + H_\alpha(p) \right]
```

where $`H_\alpha`$ is the Tsallis entropy. For $`\alpha > 1`$, the output becomes increasingly sparse. For $`\alpha = 1`$: softmax. For $`\alpha = 2`$: sparsemax. This provides a continuous parameter controlling sparsity — $`\alpha`$ can itself be learned.

### 8.4 Gumbel-Softmax: Differentiable Discrete Sampling

When a model needs to **sample** from a categorical distribution (not just compute its probability), the non-differentiability of sampling blocks gradient flow. The Gumbel-Softmax reparameterisation [8] provides a solution:

```math
y_j = \frac{\exp((z_j + g_j)/\tau)}{\sum_k \exp((z_k + g_k)/\tau)}, \quad g_j \sim \text{Gumbel}(0, 1)
```

where $`\tau`$ is a temperature parameter and $`g_j = -\log(-\log U_j)`$ with $`U_j \sim \text{Uniform}(0,1)`$.

**Properties:**
- As $`\tau \to 0`$: output approaches one-hot sample from categorical distribution
- As $`\tau \to \infty`$: output approaches uniform distribution
- Gradients flow through the softmax operation regardless of $`\tau`$

**Relevance:** Used in VAEs with categorical latent variables, text generation with discrete tokens, and reinforcement learning with discrete action spaces — showing the generality of temperature-parameterised softmax.

## 9. The Softmax in BERT's Architecture: Layer-by-Layer

### 9.1 Attention Softmax vs. Classification Softmax

BERT uses softmax in two distinct contexts:

**Attention softmax:** Within each self-attention head, softmax normalises attention scores:
```math
\alpha = \text{softmax}(QK^T/\sqrt{d_k})
```
Temperature here is always implicitly $`\sqrt{d_k}`$ (the scaling factor).

**Classification softmax:** After the final linear layer on `[CLS]`:
```math
\hat{p} = \text{softmax}(Wh_{[CLS]} + b)
```
**This** is the classification distribution where a post-hoc temperature $`T`$ can be inserted for calibration: $`\hat{p} = \text{softmax}((Wh_{[CLS]} + b)/T)`$.

### 9.2 The Logit Distribution Across Training

During BERT fine-tuning on a mental health task:

**Epoch 0 (random initialisation):** Logits are small and nearly uniform (due to small $`\|W\|`$). Softmax output is close to $`1/C`$. ECE is high — the model says ~25% for each class but accuracy is ~25%.

**Epoch 1–2:** Logits grow. The model quickly achieves reasonable accuracy. ECE may actually decrease initially.

**Epoch 3–5:** Model begins overfitting to training distribution. Logit magnitudes grow significantly. The model is very confident on training examples. ECE grows on validation/test set.

**Post fine-tuning:** ECE on out-of-domain test data can be 10–20%. The model outputs 0.95+ confidence on inputs where it should output 0.5–0.6.

### 9.3 Weight Norm as a Calibration Indicator

The norm of the classification layer weights $`\|W_j\|_2`$ directly controls logit magnitude. After fine-tuning:

```math
z_j = W_j h + b_j, \quad |z_j| \leq \|W_j\|_2 \cdot \|h\|_2 + |b_j|
```

If $`\|W_j\|_2`$ grows during fine-tuning (common without strong weight decay), logit magnitudes grow, causing overconfidence. Monitoring $`\|W_j\|_2`$ across fine-tuning epochs is a practical calibration diagnostic.

## 10. Practical Calibration Assessment in PyTorch

### 10.1 Computing ECE from Model Outputs

```python
import torch
import numpy as np

def compute_ece(probs: torch.Tensor, labels: torch.Tensor, n_bins: int = 15) -> float:
    """
    Expected Calibration Error.
    probs: (N, C) softmax probabilities
    labels: (N,) integer class labels
    """
    confidences, predictions = probs.max(dim=1)  # (N,)
    accuracies = predictions.eq(labels)           # (N,) bool
    
    ece = 0.0
    bin_boundaries = torch.linspace(0, 1, n_bins + 1)
    
    for bin_lower, bin_upper in zip(bin_boundaries[:-1], bin_boundaries[1:]):
        # Samples in this confidence bin
        in_bin = confidences.gt(bin_lower.item()) * confidences.le(bin_upper.item())
        prop_in_bin = in_bin.float().mean()
        
        if prop_in_bin.item() > 0:
            accuracy_in_bin = accuracies[in_bin].float().mean()
            avg_confidence_in_bin = confidences[in_bin].mean()
            ece += torch.abs(avg_confidence_in_bin - accuracy_in_bin) * prop_in_bin
    
    return ece.item()
```

### 10.2 Reliability Diagram Interpretation

```
 Accuracy │
      1.0 │                              ● Perfect calibration (diagonal)
      0.9 │                         ●  ●
      0.8 │                   ●  ●       ← Actual model (below diagonal)
      0.7 │             ●  ●             ← OVERCONFIDENT: says 80%, is 70%
      0.6 │       ●  ●
      0.5 │  ●  
      0.4 │
          └────────────────────────────────────
          0.5   0.6   0.7   0.8   0.9   1.0
                        Confidence
```

- **If the curve is below the diagonal:** Model is overconfident (most common for modern deep models)
- **If the curve is above the diagonal:** Model is underconfident (less common, can occur with heavy regularisation)
- **If the curve matches the diagonal:** Perfect calibration

For clinical decision support, the curve below the diagonal in the high-confidence region (0.8–1.0) is most dangerous — the model says "I'm very sure" when it is actually only moderately accurate.
